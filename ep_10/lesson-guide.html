1. عنوان جلسه

دفتر هزینه و کنترل بودجه

  • جلسهٔ دهم
  • پروژهٔ پایانی پایتون مقدماتی ۱

2. اهداف یادگیری

اهداف یادگیری

  • تبدیل یک نیاز روزمره به داده‌ها، منو و گام‌های روشن
  • ترکیب ورودی، شرط، حلقه و ساختارهای داده در یک برنامه
  • آزمایش ثبت، حذف و گزارش هزینه با ورودی معمولی و نامعتبر

تمرکز جلسه روی ساخت پروژه است. مرور مفاهیم فقط در جایی انجام می‌شود که در پروژه استفاده می‌شوند. زمان پیشنهادی برای کارگاه ۱۲۰ دقیقه است.

3. مرور جلسه قبل

مرور Dictionary در پروژه

  • یک هزینه را با کلیدهای id، title، amount و category توصیف می‌کنیم.
  • برای نگهداری چند هزینه، دیکشنری‌ها را داخل یک List می‌گذاریم.
  • حلقهٔ for رکوردها را می‌خواند و مجموع هزینه‌ها را محاسبه می‌کند.

از هنرجو بخواهید دسترسی expenses[0]["amount"] را توضیح دهد. ابتدا عضو List و سپس مقدار یک کلید در Dictionary انتخاب می‌شود.

4. آموزش مبحث اول

مسئلهٔ پروژه

  • کاربر می‌خواهد بداند چه مقدار خرج کرده و چه مقدار از بودجه باقی مانده است.
  • هر هزینه عنوان، مبلغ و دسته دارد و باید قابل حذف باشد.
  • برنامه در ترمینال اجرا می‌شود و کاربر از منو فرمان می‌دهد.

خروجی آموزشی پروژه یک ابزار محلی برای ثبت هزینه‌های همان اجرا است. تاریخ، حساب بانکی و ذخیره‌سازی دائمی جزو این نسخه نیستند.

قرارداد ورودی و خروجی

  • همهٔ مبالغ، عدد صحیح مثبت و بر حسب تومان هستند.
  • بودجه و مبلغ حداکثر ۹ رقم دارند. عنوان خالی پذیرفته نمی‌شود.
  • خروجی گزارش: مجموع، باقی‌مانده و هزینهٔ هر دسته.

صفر، عدد منفی، اعشار، جداکنندهٔ هزارگان و متن در مبلغ پذیرفته نمی‌شوند. ارقام ده‌دهی فارسی و انگلیسی قابل قبول‌اند. حداکثر ۹ رقم، قاعدهٔ همین پروژه است.

نقشهٔ داده‌ها

  • Tuple دسته‌های ثابت را نگه می‌دارد. List فهرست هزینه‌ها را نگه می‌دارد.
  • هر Dictionary یک هزینه است. Set دسته‌های استفاده‌شده را بدون تکرار نگه می‌دارد.
categories = ("Food", "Transport", "Education", "Other")
expenses = []
next_id = 1
used_categories = set()

در فایل نهایی، عنوان دسته‌ها فارسی است. برای خوانایی اسلاید، مقادیر نمونه انگلیسی‌اند. شناسهٔ رکورد با موقعیت آن در List فرق دارد.

منوی برنامه

  • حلقهٔ while منو را دوباره نشان می‌دهد.
  • if و elif فرمان انتخاب‌شده را اجرا می‌کنند. گزینهٔ صفر با break خارج می‌شود.
while True:
    choice = input("1:Add 2:List 3:Report 4:Delete 0:Exit ")
    if choice == "0":
        break
    elif choice == "1":
        print("Add expense")

این کد فقط نمای سادهٔ جریان منو است. نسخهٔ کامل، ورودی منو را اعتبارسنجی و ارقام فارسی را هم به int تبدیل می‌کند. از project_starter.py برای شروع کارگاه استفاده کنید.

ساخت مرحله‌ای

  • مرحلهٔ اول: بودجه، منو و خروج از برنامه
  • مرحلهٔ دوم: ثبت و نمایش هزینه‌ها
  • مرحلهٔ سوم: گزارش، حذف و آزمایش حالت‌های مرزی

پیش از افزودن قابلیت بعدی، همان بخش فعلی را اجرا کنید. ابتدا از دادهٔ ثابت استفاده کنید، سپس input و اعتبارسنجی را اضافه کنید. پاسخ کامل را پس از تلاش اولیه نشان دهید.

5. مثال مبحث اول

مثال اول: بررسی مبلغ

  • متن را پاک‌سازی می‌کنیم و پیش از int، معتبر بودن آن را می‌سنجیم.
amount_text = " 200000 ".strip()
if amount_text.isdecimal() and len(amount_text) <= 9:
    amount = int(amount_text)
    if amount > 0:
        print("Valid amount:", amount)
    else:
        print("Amount must be positive")
else:
    print("Invalid amount")

isdecimal برای رقم‌های ده‌دهی مناسب است. isdigit بعضی نویسه‌ها مانند ² را هم رقم می‌داند، اما int آن‌ها را نمی‌پذیرد. در فایل پروژه، ورودی نامعتبر با continue به منو برمی‌گردد. منبع: https://docs.python.org/3/library/stdtypes.html#str.isdecimal

پاسخ و توضیح

برای متن نمونه، مقدار معتبر 200000 است. ورودی‌های -5، 1.5، 1,000 و متن خالی نامعتبرند.

مثال اول: ثبت یک رکورد

  • پس از تأیید همهٔ ورودی‌ها، یک Dictionary تازه می‌سازیم.
expense = {
    "id": next_id,
    "title": "Book",
    "amount": 200000,
    "category": "Education",
}
expenses.append(expense)
next_id += 1

کد این اسلاید ادامهٔ نقشهٔ داده‌ها است. next_id و expenses از قبل ساخته شده‌اند. اگر ورودی ناقص است، هیچ رکوردی به List اضافه نکنید. هر ثبت باید یک دیکشنری تازه داشته باشد.

مثال اول: نمایش هزینه‌ها

  • برای فهرست خالی پیام روشن می‌دهیم. هر رکورد شناسهٔ خودش را نمایش می‌دهد.
if len(expenses) == 0:
    print("No expenses")
else:
    for expense in expenses:
        print(expense["id"], expense["title"])
        print(expense["amount"], expense["category"])

این قطعه ادامهٔ مثال ثبت است. شناسه را هنگام نمایش حتماً چاپ کنید تا کاربر برای حذف، شناسهٔ درست را بشناسد.

6. آموزش مبحث دوم

گزارش مجموع و باقی‌مانده

  • جمع را هر بار از رکوردهای فعلی می‌سازیم تا حذف هزینه هم در گزارش اثر کند.
budget = 1000000
total = 0
for expense in expenses:
    total += expense["amount"]
remaining = budget - total
print(total, remaining)

این قطعه ادامهٔ مثال با expenses موجود است. total خارج از حلقهٔ for صفر می‌شود. برای فهرست خالی، total برابر صفر و remaining برابر کل بودجه می‌ماند.

گزارش دسته‌ها

  • نام دسته، کلید دیکشنری گزارش است و مقدار آن جمع هزینه‌های آن دسته است.
category_totals = {}
for category in categories:
    category_totals[category] = 0
for expense in expenses:
    category = expense["category"]
    category_totals[category] += expense["amount"]
for category, amount in category_totals.items():
    print(category, amount)

دستهٔ رکورد باید یکی از دسته‌های مجاز باشد. این شرط در زمان ثبت کنترل می‌شود. دیکشنری گزارش را با صفرهای اولیه می‌سازیم تا دستهٔ بدون هزینه هم نمایش داده شود.

نقش Set در گزارش

  • یک دسته ممکن است در چند رکورد تکرار شود. Set فقط نام‌های یکتا را نگه می‌دارد.
used_categories = set()
for expense in expenses:
    used_categories.add(expense["category"])
print(len(used_categories))

مجموعه را هر بار از expenses فعلی دوباره بسازید. اگر آخرین هزینهٔ یک دسته حذف شد، آن دسته نباید در شمارش باقی بماند. برای خالی ساختن Set از set() استفاده می‌کنیم، نه {}.

حذف با شناسه

  • شناسه ثابت می‌ماند، حتی اگر جای رکوردها در List عوض شود.
  • پس از پیدا کردن رکورد و pop، با break پیمایش را پایان می‌دهیم.
target_id = 2
found = False
for index in range(len(expenses)):
    if expenses[index]["id"] == target_id:
        expenses.pop(index)
        found = True
        break
if not found:
    print("ID not found")

این قطعه به expenses موجود نیاز دارد. مقدار 2 شناسه است، نه اندیس 2. شناسهٔ رکورد تازه از next_id می‌آید و با len(expenses) محاسبه نمی‌شود.

حالت‌های بودجه

  • باقی‌ماندهٔ مثبت: بخشی از بودجه هنوز مصرف نشده است.
  • باقی‌ماندهٔ صفر: بودجه دقیقاً مصرف شده است.
  • باقی‌ماندهٔ منفی: مجموع هزینه‌ها از بودجه بیشتر شده است.

اضافه شدن هزینه را صرفاً به علت عبور از بودجه ممنوع نمی‌کنیم. برنامه واقعیت هزینه را ثبت می‌کند و سپس هشدار می‌دهد. این تصمیم را با هنرجو توضیح دهید.

7. مثال مبحث دوم

مثال دوم: اجرای یک سناریوی کامل

  • بودجه: ۱٬۰۰۰٬۰۰۰ تومان. کتاب: ۲۰۰٬۰۰۰، خوراک: ۱۵۰٬۰۰۰، رفت‌وآمد: ۵۰٬۰۰۰.
  • گزارش اول: مجموع ۴۰۰٬۰۰۰ و باقی‌مانده ۶۰۰٬۰۰۰ تومان.
  • پس از حذف هزینهٔ خوراک: مجموع ۲۵۰٬۰۰۰ و باقی‌مانده ۷۵۰٬۰۰۰ تومان.

در فایل نهایی دستهٔ خوراک گزینهٔ ۱، رفت‌وآمد گزینهٔ ۲ و آموزش گزینهٔ ۳ است. به همین ترتیب رکوردها شناسه‌های ۱، ۲ و ۳ می‌گیرند. برای حذف خوراک شناسهٔ ۲ را وارد کنید. فایل demo_input.txt ورودی همین اجرا را دارد.

مثال دوم: بررسی نتیجهٔ حذف

  • پیش از حذف، سه دسته استفاده شده‌اند. پس از حذف خوراک، دو دسته باقی می‌مانند.
  • شناسهٔ رکورد بعدی ۴ است؛ شناسهٔ ۲ دوباره استفاده نمی‌شود.
  • گزارش تازه باید از List فعلی محاسبه شود.

از هنرجو بخواهید بدون نگاه به پاسخ، تغییر گزارش دسته‌ها و next_id را توضیح دهد. این بخش هم‌زمان Dictionary، Set، List و شرط را مرور می‌کند.

8. نکات مهم

نکات مهم پروژه

  • داده‌ها فقط در حافظه‌اند و پس از خروج ذخیره نمی‌شوند.
  • عدد صحیح تومان، محاسبات این نسخه را ساده و قابل بررسی نگه می‌دارد.
  • ورودی نامعتبر نباید رکورد ناقص بسازد یا برنامه را متوقف کند.

محدودیت ذخیره‌سازی را پیش از دمو اعلام کنید. فایل، JSON، try/except، تابع، کلاس و پایگاه داده جزو پیاده‌سازی فعلی نیستند. این‌ها می‌توانند موضوع ادامهٔ مسیر باشند.

آموخته‌های دوره در یک برنامه

  • رشته و تبدیل نوع برای ورودی، و شرط برای اعتبارسنجی و انتخاب فرمان
  • while برای منو، for برای گزارش و break و continue برای کنترل جریان
  • List برای رکوردها، Dictionary برای جزئیات، Tuple برای دسته‌ها و Set برای یکتاها

هر هنرجو یک قابلیت را انتخاب کند و بگوید کدام جلسه به ساخت آن کمک کرده است. از تبدیل این مرور به آموزش مبحث تازه خودداری کنید.

9. خطاهای رایج

خطاهای رایج: ورودی و رکورد

  • تبدیل مستقیم متن نامعتبر با int، برنامه را با خطا متوقف می‌کند.
  • ذخیرهٔ مبلغ به‌صورت str باعث خطا در جمع هزینه‌ها می‌شود.
  • استفادهٔ دوباره از همان Dictionary می‌تواند چند رکورد را ناخواسته مشترک کند.

در نمونهٔ کامل، تبدیل نوع بعد از بررسی متن انجام می‌شود و ساخت expense درون شاخهٔ ثبت قرار دارد. برای هر هزینه دیکشنری تازه ساخته می‌شود.

خطاهای رایج: گزارش و حذف

  • صفرکردن total داخل for، جمع نهایی را اشتباه می‌کند.
  • اشتباه گرفتن id با index می‌تواند رکورد دیگری را حذف کند.
  • ادامهٔ پیمایش پس از pop ممکن است اعضا را رد کند؛ بلافاصله break لازم است.

شناسهٔ ناموجود باید پیام مناسب بدهد و داده‌ها را تغییر ندهد. برای بررسی این حالت، شناسهٔ 99 را وارد کنید.

10. تمرین کلاسی

تمرین کلاسی: ساخت پروژه

  • از project_starter.py شروع کنید و ابتدا ثبت و نمایش را تکمیل کنید.
  • سپس گزارش مجموع، دسته‌ها و حذف با شناسه را اضافه کنید.
  • دو نفره کار کنید: یک نفر ورودی می‌دهد و نفر دیگر نتیجهٔ مورد انتظار را پیش‌بینی می‌کند.

زمان پیشنهادی ۳۰ تا ۴۰ دقیقه. در هر مرحله یک اجرای کوتاه انجام شود. budget_tracker.py پاسخ مرجع است، نه نقطهٔ شروع تایپ هنرجو.

تمرین کلاسی: سناریوهای پذیرش

  • فهرست خالی، شناسهٔ غایب و گزینهٔ نامعتبر باید پیام روشن داشته باشند.
  • مبلغ خالی، منفی، اعشاری و صفر نباید ثبت شوند.
  • پس از حذف، مجموع و تعداد دسته‌ها اصلاح شوند و شناسهٔ بعدی تکراری نشود.

حالت بودجهٔ مصرف‌شده و عبور از بودجه را هم آزمایش کنید. فایل test_cases.md ورودی و خروجی مورد انتظار هر سناریو را مشخص می‌کند.

11. کوییز کوتاه

کوییز کوتاه پروژه

  • ۱. چرا هر هزینه Dictionary است ولی مجموعهٔ هزینه‌ها List است؟
  • ۲. چرا شناسهٔ بعدی را با طول List محاسبه نمی‌کنیم؟
  • ۳. پس از حذف یک هزینه، چرا گزارش و Set دسته‌ها را دوباره می‌سازیم؟
پاسخ و توضیح

۱. رکورد فیلدهای نام‌دار دارد و List چند رکورد را نگه می‌دارد. ۲. حذف، طول List را کم می‌کند و می‌تواند شناسهٔ تکراری بسازد. ۳. گزارش باید وضعیت فعلی را منعکس کند و ممکن است آخرین هزینهٔ یک دسته حذف شده باشد.

12. تمرین منزل

تمرین منزل و تحویل پروژه

  • نسخهٔ کامل را تحویل دهید و یک اجرای نمونه همراه با توضیح داده‌ها ارائه کنید.
  • با همان مباحث، قابلیت جست‌وجوی هزینه‌ها بر اساس بخشی از عنوان را اضافه کنید.
  • برای نتیجهٔ خالی و تفاوت حروف بزرگ و کوچک، آزمون بنویسید یا اجرای نمونه ارائه دهید.

جست‌وجو با strip و lower و عملگر in روی title و یک حلقه انجام می‌شود. تابع یا کتابخانهٔ جدید لازم نیست. معیار ارزیابی و پاسخ پیشنهادی در راهنمای جلسه آمده است.

13. جمع‌بندی

جمع‌بندی و ادامهٔ مسیر

  • یک مسئلهٔ روزمره را به داده، ورودی، منو و گزارش تبدیل کردیم.
  • با اجرای سناریوهای مرزی، درست بودن رفتار برنامه را بررسی کردیم.
  • گام بعدی: مقدماتی ۲، تقسیم برنامه به تابع و ذخیره‌سازی داده.

هدف پایان دوره، توانایی توضیح و تغییر همین برنامه است. هنرجو باید بتواند دلیل انتخاب هر ساختار داده را بگوید و یکی از قابلیت‌ها را بدون کپی‌کردن دوباره بسازد.
